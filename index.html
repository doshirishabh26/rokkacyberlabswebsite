1 · W2 Employer Cost Calculator
Budget Calculator Job Details cost card State-aware Per-position labor type

What it does Shipped

Production managers now see what a job actually costs the company once W2 employer burden is added on top of crew wages — broken down per state, per position, and per labor type.

Per-position cost tile

  • Each crew position renders its own collapsible "Show cost breakdown" section
  • Gross wages, Workers' Comp (rate % + labor type), other employer burden, position subtotal
  • W2 rows hidden automatically for 1099 contractor positions

Itemised W2 burden

  • FICA, FUTA, SUTA, Workers' Comp, State Disability, Payroll Processing — each line shows its own rate and dollar amount
  • Effective Burden % rolls up the components into the headline rate the company sees
  • Blended WC% shown when positions have different labor types on the same job

State-aware

  • Reads admin-managed rates from DynamoDB first, falls back to legacy hardcoded defaults if the state isn't seeded yet
  • UI surfaces "rates as of YYYY-MM-DD (admin-managed)" vs "(legacy default)" for transparency
  • Hidden on tour jobs (tour cost model is per-stop, not per-call)

2 · Admin tooling & weekly drift cron
Admin portal EventBridge cron Human-in-the-loop

How the rates stay current Operations

Tax rates are admin-managed in DynamoDB. A weekly cron compares our stored values against authoritative government pages and emails admins on drift — it never auto-updates.

Admin portal pages

  • State Rules — per-state CRUD for FICA / FUTA / SUTA / WC / SDI / PFL components, with effective dates and source URLs
  • Labor Types — 10 Workers' Comp buckets (Stagehand, Rigging, Driver, Production Management, etc.) with editable WC rates
  • Skills — every skill mapped to one Labor Type, so each crew position auto-resolves its WC rate

Two-tier WC model

  • State baseline — average stagehand-class WC % per state, used as fallback
  • Labor-type override — per-position WC % wins when a Labor Type is mapped (Rigger 5.5% vs Coordinator 1.5%)
  • Same job, mixed positions → blended WC% shown to the customer

Weekly drift cron

  • Lambda stateRulesSourceCheckCron, schedule cron(0 14 ? * MON *) — every Monday 14:00 UTC
  • Fetches SSA, IRS, CA EDD, NY DOL pages; regex-extracts the published rate
  • Compares against DDB — drift ≥ 0.05 percentage points triggers an email to every active admin
  • Never auto-updates — admin reviews the diff and explicitly approves the new rate
  • Per-source failures (page format change, network blip) surface in the alert email — don't block the rest of the run

3 · Tour multi-city support
Job wizard Tour itinerary Email + map

Multi-stop tour jobs Shipped

Tour jobs are no longer modeled as a single start/end location — they're an ordered itinerary of stops, with per-stop venue and date.

Stop builder

  • Each tour stop has a venue (autocomplete), city, state, and date range
  • Chronological validation — stops must be ordered by date, overlaps flagged
  • Travel-day gap warning — if two stops are < 1 day apart in distant cities, the wizard surfaces a heads-up

Crew-facing surfaces

  • Offer + invite emails now include the full tour itinerary as a readable list
  • Google Maps directions link (route across all stops in order) embedded in the email
  • Crew app tour cards render the itinerary instead of "City → City" only

Behind the scenes

  • job.tourStops[] on the Job record; startLocation/endLocation auto-derived from first & last stop
  • Backward-compatible — pre-existing tour jobs without tourStops still render the legacy route
  • Tour positions reference stop index when needed for per-leg crew assignment
4 · Call sheet copy & paste
Call Schedule step Bulk editor CSV in / out

Bulk edit calls without clicking 200 times Shipped

For a 50-position multi-day job, editing call times one cell at a time is brutal. The bulk editor lets PMs round-trip the entire call schedule through Excel/Sheets.

Export CSV

  • One row per call: key, position, crew_needed, date, call_type, start_time, end_time, duration_hrs
  • Headers include timezone + valid call_type list as commented lines
  • Open in Excel/Sheets, edit anywhere, paste back

Paste + diff preview

  • Paste from clipboard → parser detects timezone + format mismatches
  • Diff preview shows only the cells that will change — no surprises on apply
  • Overnight calls (end < start) auto-bump the end date by 1 day
  • "No changes detected" message when paste matches current in-memory form state

In-app bulk apply bar

  • Select N rows with checkboxes → apply bar slides up sticky at the bottom
  • Apply call type + start time + end time across the selection
  • Dates are intentionally not touched — bulk time-of-day changes across multi-day schedules without scrambling the calendar
  • OT flags built in: > 10h amber, > 14h red duration warnings inline
5 · Grouping calls into shifts
Call Sheet tab Groups panel Replaces legacy Shifts

Calls collapse by day & window Shipped

Long jobs used to render as a wall of identical-looking calls. The new groups panel buckets calls into shifts so the PM and crew see "Day 2 morning load-in" instead of seventeen overlapping rows.

Auto-grouping rules

  • Calls on the same date with overlapping or adjacent windows collapse into one shift card
  • Different call types (load-in, show, strike) stay visually distinct inside the same shift
  • All times rendered in the job's configured timezone — no client-locale drift

What each group shows

  • Shift label (Day N · morning/afternoon/evening)
  • Roster: every crew member assigned to any call in the shift, with their per-call window
  • Crew with zero shift memberships render once at the bottom — layout only shifts when needed

What replaced what

  • Old Shifts panel + standalone Crew tab → unified Groups panel
  • Bulk-shift-call-times deliberately not shipped — that's owned by the bulk paste editor above
  • Groups are derived (not stored) — editing a call's time automatically re-groups, no manual sync
